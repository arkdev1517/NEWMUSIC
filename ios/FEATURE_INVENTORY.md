# BitChord iOS migration inventory

This inventory was built from the checked-in Android/Kotlin implementation before the iOS target was added. The Android tree remains the product and contract source of truth. It contains 258 Android app Kotlin/Java source files plus shared Kotlin code; there was no existing Xcode project, Swift source, or Swift package. The initial Git working tree was clean on `arena/e831339a-newmusic`.

## Backend and persistence facts

- The music catalogue is accessed by the shared JVM `Innertube` client at `https://music.youtube.com/youtubei/v1` with `WEB_REMIX` client context, live client version, language/region and optional cookie/session headers. `shared/src/jvmSharedMain/kotlin/com/music/bitchord/data/innertube/Innertube.kt` is the concrete contract; `InnertubeParser.kt` parses renderer responses. This is an unofficial web-client API, not a BitChord-owned backend.
- `shared/src/commonMain/kotlin/com/music/bitchord/data/model/Models.kt` defines `Song`, `BrowseItem`, `SearchResult`, `SearchFilter`, `HomeShelf`, `DetailPage`, `LibraryPage`, `UiState` and related domain types.
- Android preferences use `SharedPreferences` (`AppSettings.kt`, `SearchHistory.kt`, `Downloads.kt`, local playlist/source settings); credentials and source definitions use `EncryptedPrefs` + Android Keystore where available. Local listening data and source-specific caches have separate stores.
- Optional Last.fm secrets are read from local Gradle properties or environment (`app/build.gradle.kts`); none should be copied into an iOS bundle. Listen Together's public server URL is a build default, user-overridable and not a credential.

## Native iOS status and parity tracking

The native iOS target is at `ios/BitChord/BitChord.xcodeproj` (shared `BitChord` scheme; app + XCTest targets; iOS 17 minimum). It is a real SwiftUI app built around URLSession, Keychain, AVPlayer/AVAudioSession, MediaPlayer, `fileImporter`, and explicit service injection. It is independent of Gradle and Android SDKs. Source-code coverage below is not a claim of a passing native build: this Linux workspace has no Xcode, Swift compiler, iOS SDK, or simulator.

### Remaining feature gaps and platform-specific choices

- Android onboarding, account/channel switching, full playback/history screens, saved playlists/subscriptions, playlist management, local folder scanning, and offline downloads are not ported. The iOS local-audio alternative is user-selected import from Files into app-private storage; Android MediaStore-wide scanning and a foreground download service have no direct iOS equivalent.
- Addon/QuickJS modules, JioSaavn and other source integrations, lyrics providers/synced lyrics, animated Canvas artwork, Last.fm/ListenBrainz scrobbling, listening statistics/Replay, backup/export, artist facts, Discord, Spotify account/library, and source-management/settings pages remain unimplemented.
- Android widgets, Wear OS and Google Cast are not included. Potential iOS counterparts would be WidgetKit, a separate watchOS app, and AirPlay/AVPlayer external playback; CarPlay requires a distinct entitlement/product design and is not claimed here.
- Stream extraction is a significant unresolved dependency: the iOS client only selects direct iOS-compatible audio URLs. Android's InnerTubeX/NewPipe resolver, PoToken generation, client fallback, and JavaScript signature/`n` deciphering are not implemented, so remote playback is best effort and can fail for many streams.
- YouTube Music is accessed through an unofficial InnerTube web-client API. Its renderer formats, auth requirements, endpoint availability and stream policies can change without notice. Google may block sign-in in an embedded web view; there is no supported OAuth flow in this port.
- Custom Listen Together server URLs require HTTPS under iOS App Transport Security. The default points to the repository's deployed service. Live service availability and deployment are external dependencies.
