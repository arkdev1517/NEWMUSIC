# BitChord iOS migration inventory

This inventory was built from the checked-in Android/Kotlin implementation before the iOS target was added. The Android tree remains the product and contract source of truth. It contains 258 Android app Kotlin/Java source files plus shared Kotlin code; there was no existing Xcode project, Swift source, or Swift package. The initial Git working tree was clean on `arena/e831339a-newmusic`.

## Backend and persistence facts

- The music catalogue is accessed by the shared JVM `Innertube` client at `https://music.youtube.com/youtubei/v1` with `WEB_REMIX` client context, live client version, language/region and optional cookie/session headers. `shared/src/jvmSharedMain/kotlin/com/music/bitchord/data/innertube/Innertube.kt` is the concrete contract; `InnertubeParser.kt` parses renderer responses. This is an unofficial web-client API, not a BitChord-owned backend.
- `shared/src/commonMain/kotlin/com/music/bitchord/data/model/Models.kt` defines `Song`, `BrowseItem`, `SearchResult`, `SearchFilter`, `HomeShelf`, `DetailPage`, `LibraryPage`, `UiState` and related domain types.
- Android preferences use `SharedPreferences` (`AppSettings.kt`, `SearchHistory.kt`, `Downloads.kt`, local playlist/source settings); credentials and source definitions use `EncryptedPrefs` + Android Keystore where available. Local listening data and source-specific caches have separate stores.
- Optional Last.fm secrets are read from local Gradle properties or environment (`app/build.gradle.kts`); none should be copied into an iOS bundle. Listen Together's public server URL is a build default, user-overridable and not a credential.

## Native iOS status and parity tracking

The native iOS target is at `ios/BitChord/BitChord.xcodeproj` (shared `BitChord` scheme; app + XCTest targets; iOS 17 minimum). It is a native SwiftUI app built around URLSession, Keychain, AVPlayer/AVAudioSession, MediaPlayer, JavaScriptCore, `fileImporter`, and explicit service injection. It is independent of Gradle and Android SDKs. Source-code coverage below is not a claim of a passing native build: this Linux workspace has no Xcode, Swift compiler, iOS SDK, or simulator. Everything in the "source-level" table is implemented and statically audited, but **nothing has been compiled or run**.

### Remaining feature gaps and platform-specific choices

- **PoToken/BotGuard** (see stream resolution above) is the one Android playback subsystem with no iOS counterpart here: Android generates PoTokens in a WebView (`PoTokenWebView.kt`); doing the equivalent on iOS means hosting the BotGuard challenge in a `WKWebView`, which is a project of its own and is not pretended at.
- **Pluggable sources**: the Addon JSON protocol, QuickJS/Spine modules, JioSaavn matching, and the Sources management screens are not ported. Consequently Android's lossless-above-256k quality rungs (which come from addon sources there) cap at YouTube's AAC on iOS — the ladder and ceilings are implemented exactly; the catalogue behind the top rungs is the gap.
- **Canvas animated artwork** (Spotify/Tidal/Apple Music), **artist facts**, **Discord rich presence** and the **Spotify library/canvas** integrations are separate third-party contracts and are not ported.
- **Account/channel switching**: Android keeps multiple signed-in profiles (`AccountSessions.kt`); the iOS port holds one cookie session.
- **Audio pipeline**: no equalizer/DSP graph, and Android-only output knobs (USB DAC routing, PCM/DSD output modes, refresh-rate forcing) have no iOS API surface and are deliberately not stored as inert toggles. Skip-silence is not implemented (AVPlayer cannot trim intra-file silence); crossfade is a volume ramp rather than a sample-exact mix.
- **Platform extensions**: Android widgets / Wear OS / Google Cast are not included. The iOS counterparts would be WidgetKit, a watchOS app and AirPlay (the route picker is present; `allowsExternalPlayback` is on). CarPlay needs its own entitlement/product design and is not claimed.
- **Feedback menu tokens** (InnerTube menu actions such as "not interested"): the parser does not extract them, so those menu entries are absent rather than dead.
- YouTube Music is accessed through an unofficial InnerTube web-client API. Renderer formats, auth requirements, endpoint availability and stream policies can change without notice. Google may block sign-in in an embedded web view; there is no supported OAuth flow in this port.
- Custom Listen Together server URLs require HTTPS under iOS App Transport Security. The default points to the repository's deployed service.
